## 2025-02-14 - Fix Hardcoded JWT Secret and Error Leakage
**Vulnerability:** A hardcoded fallback JWT secret (`super-secret-jwt-key-with-high-entropy-minimum-32-chars`) was used if `JWT_SECRET` was missing in development. Additionally, internal stack traces/error messages were leaked through 500 response codes in `backend/server.ts` and `backend/router.ts`.
**Learning:** Hardcoded default secrets can easily lead to tokens being predictable or exploitable in non-production environments that may still be accessible over a network. Leaking raw `err.message` in HTTP 500 responses can expose sensitive backend logic or database details to clients.
**Prevention:** Always fallback to securely generated random secrets (`crypto.randomBytes(32).toString('hex')`) in development if environment secrets are not provided. For error handling, map unexpected internal errors to a generic client-facing message like "Internal Server Error", and log the actual error stack on the server side only.
## 2025-02-12 - [Critical] Fixed IDOR in landlord stats endpoints
**Vulnerability:** The `/stats` and `/landlord/stats` endpoints were public and missing authentication (`authenticateToken`), leading to Insecure Direct Object Reference (IDOR). Attackers could enumerate `landlordId` queries and fetch financial stats (`balance`, `totalRevenue`, `totalWithdrawn`) for any landlord.
**Learning:** Some backend routes referencing financial metrics might miss JWT verification during initial implementation.
**Prevention:** Ensure all routes accessing user-specific sensitive data are protected with `authenticateToken`, `requireRole`, and IDOR-prevention logic confirming ownership (`req.user.id === requestedId` or `req.user.role === 'admin'`).
