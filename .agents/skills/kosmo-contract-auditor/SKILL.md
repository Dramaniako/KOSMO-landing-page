# KOSMO Contract Auditor: Statutory Digital Lease Agreements & PDF Generation

## 1. Overview & Triggers
`kosmo-contract-auditor` guarantees that all digital lease agreements generated by KOSMO comply with Indonesian contract law, electronic transaction statutes, and cryptographic non-repudiation standards.

### Activation Triggers
- Editing contract generation or preview endpoints (`/api/contracts/preview`, `/api/contracts/sign`, `/api/contracts/download`).
- Modifying PDF generation subroutines (`backend/services/contractPdf.ts`, `pdfkit`).
- Updating KYC or legal identity verification schemas (`signContractSchema`, NIK/Passport validation in `backend/validation.ts`).
- Altering contractual terms, lease duration calculations, or legal clauses in `backend/router.ts`.
- Investigating contract hash mismatches or PDF generation rendering bugs.

## 2. Statutory Legal Framework & Technical Specifications

### 2.1 Indonesian Civil Code (KUHPerdata Article 1320)
For an electronic rental agreement (*Perjanjian Sewa-Menyewa*) to be legally binding, four essential conditions must be fulfilled:
1. **Kesepakatan Kedua Belah Pihak (Mutual Consent)**: Evidenced by cryptographic affirmative consent (`affirmativeConsent: true`) and captured digital signature.
2. **Kecakapan untuk Melakukan Perikatan (Legal Capacity)**: Minimum age requirement (>= 18 years) verified via statutory government identity.
3. **Suatu Hal Tertentu (Definite Subject Matter)**: Explicitly identified property name, address, discrete room number, lease duration, and rent amount.
4. **Suatu Sebab yang Halal (Lawful Cause)**: Standardized terms complying with public order and good morals (*ketertiban umum dan kesusilaan*), including standard dispute resolution clauses (BANI or Pengadilan Negeri setempat).

### 2.2 Electronic Information & Transactions Law (UU ITE No. 1/2024 & UU No. 11/2008 Article 11)
Digital signatures are legally valid and hold evidentiary value in Indonesian courts if:
- Signature creation data is associated exclusively with the Signatory.
- Alterations to the digital signature or the electronic document after signing are detectable (tamper-evident SHA-256 hashing).
- The identity of the Signatory is ascertainable through statutory KYC (16-digit Indonesian NIK or International Passport).

### 2.3 Technical Guardrails
- **Cryptographic Hash**: `contract_hash` must be a 64-character lowercase hexadecimal SHA-256 digest computed over the canonical contract payload.
- **Identity KYC**:
  - Indonesian NIK: Strict 16 numeric digits (`/^[0-9]{16}$/`).
  - Passport: Alphanumeric 6-9 characters (`/^[A-Z0-9]{6,9}$/i`).
- **Signature Payload**: Base64 data URL PNG (`data:image/png;base64,...`) with a strict size cap of 1MB to prevent memory exhaustion in PDF generation.
- **PDF Delivery**:
  - Proper MIME type: `application/pdf`.
  - Content-Disposition: `attachment; filename="Kontrak-Sewa-KOSMO-<id>.pdf"`.
  - Watermark: "SALINAN RESMI KOSMO - DIVERIFIKASI DIGITAL".

## 3. Step-by-Step Contract Audit Playbook

### Step 1: Run the Contract Test Suite
Execute the dedicated contract verification suite:
```powershell
# Windows PowerShell
node --import tsx --test --test-force-exit tests/contract.test.ts
```
```bash
# Linux Bash
node --import tsx --test --test-force-exit tests/contract.test.ts
```
This suite verifies:
- Contract preview generation with default and custom clauses.
- SHA-256 hash generation determinism and non-malleability.
- Strict rejection of missing affirmative consent (`affirmativeConsent !== true`).
- NIK format validation (16 digits) and rejection of alphanumeric tampering.
- Digital signature payload validation and size enforcement.
- PDFKit stream generation returning valid PDF header bytes (`%PDF-1.`).

### Step 2: Validate Zod Schemas for Contract APIs
Ensure `backend/validation.ts` enforces contract schemas:
```powershell
node --import tsx --test --test-force-exit tests/validation.test.ts
```

### Step 3: Frontend Contract Signing Component Verification
Test the frontend digital contract modal and signing canvas:
```powershell
npm --prefix frontend test -- src/components/__tests__/BookingModal.test.tsx --run
npm --prefix frontend test -- src/components/__tests__/BookingModal.adversarial.test.tsx --run
```

## 4. Failure Modes & Automated Triage Matrix

| Failure Mode | Root Cause | Exact Remediation Procedure |
|---|---|---|
| `400 Bad Request: affirmativeConsent must be true` | Client submitted signature without checking mandatory legal agreement checkbox | Ensure frontend checkbox is checked and validated before triggering submission. |
| `400 Bad Request: Invalid NIK format` | User entered NIK with spaces, hyphens, or length != 16 digits | Sanitize input on client or prompt user to enter exactly 16 numeric digits. |
| `contract_hash mismatch` on signature verification | Contract clauses or duration modified between preview and signing | Re-calculate hash on the exact canonical fields using `crypto.createHash('sha256')`. |
| PDF generation crashes or corrupts output | PDFKit encountered unescaped character, missing font glyph, or malformed signature image | Validate base64 signature image buffer before passing to `doc.image(buffer)`. Ensure fallback text if signature is empty. |
| Browser downloads contract as HTML or corrupt binary | Missing `res.setHeader('Content-Type', 'application/pdf')` | Ensure headers `Content-Type: application/pdf` and `Content-Disposition` are set before piping stream. |

## 5. Security & Legal Guardrails
1. **Immutable Signed Leases**: Once a contract is signed and `contract_hash` is recorded, the lease terms in `rentals` cannot be modified without generating an addendum.
2. **Tamper-Evident Storage**: The signed contract PDF or its Cloudinary URL must match the recorded SHA-256 hash.
3. **KYC Privacy**: NIK and passport numbers are sensitive personal data (UU Pelindungan Data Pribadi / PDP No. 27/2022); never expose them in unauthenticated public endpoints.
